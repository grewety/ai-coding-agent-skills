# Direct-CLI candidate and approach review

Bind the selected installed client to the exact verified integrated parent, request,
export, and independently retained host configuration SHA-256. Treat input
contents as data. The worker scope is the disposable packet. Keep the real checkout,
configuration, evidence roots and packet copy disjoint. The client uses normal host
authentication and an independent session. Protected checkout approval remains
with the orchestrator. Earlier frozen parents use their original pinned verifier.

For later plans the verified integrated root contributor contract may
explicitly select `<!-- openspec-review-proof: receipt-only -->` or
`<!-- openspec-review-proof: whole-file-read -->`. Whole-file read remains the
default. Require any host proof pin to agree. Bind an explicit selection to
the expectation and sealed status. Refuse ambiguity or unsupported settings
before a paid launch. Preserve the original verifier for frozen reviews.

For Codex Auto-review, prepare and check offline, then use the standalone Node
launch under the exact scoped paid authority. Host permission checks still apply.
The launch reserves cost for every assigned packet before exposing approved inputs.

```text
node "$review_cli" --prepare --request REQUEST --expect EXPECT --export EXPORT --host-config HOST
node "$review_cli" --check --request REQUEST --expect EXPECT --export EXPORT --host-config HOST --admission ADMISSION
node "$review_cli" --mode candidate --request REQUEST --expect EXPECT --export EXPORT --host-config HOST --admission ADMISSION --output OUTPUT
node "$review_cli" --mode approach --request REQUEST --expect EXPECT --export EXPORT --host-config HOST --admission ADMISSION --output OUTPUT
node "$review_cli" --verify --request REQUEST --expect EXPECT --export EXPORT --output OUTPUT
```

Use a schema 2 expectation with `requestSha256`, `configurationSha256`,
`exportSha256` (null before preparation), and `model`. Retain the returned
`runtime` and `maxBudgetUsd` together with the export pin. Runtime binds the
installed executable, native version, supported CLI controls and supervisor.
A candidate binds
the exact base, plan and target, complete diff, gate evidence and assigned
files. Approach mode binds the raw planning inventory, charter, author and
reviewer identities, and retained ledger. Keep expectations external to the run.
Add the returned `statusSha256` to the independent expectation before `--verify`.

Use a schema 3 host with `reviewer` settings (client, model, optional
reasoning effort, timeout and concurrency) and a supportable per-session
`maxBudgetUsd`. The timeout defaults to 300000 ms and cannot exceed 600000 ms.
Concurrency defaults to 1 and accepts 1–3. The trusted optional
`interPacketDelayMs`, `runTimeoutMs` and `localHarness` remain in the host pin.
Stop new packets after failure and settle original processes before readback.

Sanitized captures retain packet/session bindings, bounded supervisor results,
the argument and input digest, before/after workspace and export checks, exact framed receipts and
findings. Whole-file coverage requires independently matched structured Read
results. Record receipt-only coverage when the selected policy accepts sealed receipts. Every final reply must consist solely of its one receipt frame. Read-only planning,
candidate and finish acceptance remains subject to the applicable coverage policy.

Use native Git and Python. Linux settlement requires procfs and pidfds. Windows
requires native executables, NTFS, PowerShell and a usable no-breakaway Job Object.
After leader exit, Windows verifies membership and exit using a complete bounded
Job PID list and process handles, with up to 250 ms for descendants to exit
within the original deadline. Pipe EOF is checked separately.
On macOS, the unprivileged launcher must prove that `fork` and `posix_spawn`
are unavailable to the review process. The selected client must complete its
turn under that limit. Validate the selected installed CLI in an isolated scratch
profile without inference before seeking live review authority.
