# Packaged implementer command

The exclusive worker runtime is a candidate pending separate live qualification.
Group 1.1 uses an already-qualified standalone Codex 0.171.0 bootstrap launcher
with its independently verified narrower native named permission profile.
That bootstrap evidence applies to the launcher that authored the candidate.
The new command requires its own exact runtime and role-pair qualification.

Use Node 22 or later on Linux with Python 3, procfs and pidfds. Run the pinned
package outside the mutable checkout and supply protected records from the
orchestrator. Each absolute JSON input is a single-link sealed file under an
owner-private directory. Retain its expected SHA-256 independently. Hash
record bytes directly. Generated record hashes use compact, recursively
key-sorted JSON followed by a final LF. The portable request hash covers
the exact Markdown envelope generated by `requestBytes` in
`scripts/worker-handoff.mjs`.

```text
node run-implementer.mjs --runtime-identity
node run-implementer.mjs --inspect INPUT INPUT_SHA256
node run-implementer.mjs --run INPUT INPUT_SHA256
node run-implementer.mjs --recover INPUT INPUT_SHA256
node run-implementer.mjs --cancel INPUT INPUT_SHA256
node run-implementer.mjs --release-slot INPUT INPUT_SHA256 RELEASE RELEASE_SHA256
node run-implementer.mjs --release-claim INPUT INPUT_SHA256 RELEASE RELEASE_SHA256
```

- `--runtime-identity` hashes the exact launcher and supporting runtime files.
  `--inspect` reads the original attempt without starting a worker or
  publishing a handover.
- `--run` consumes bounded local delegation authority and attempts exclusive
  claim, slot admission, native preflight, and foreground launch. The selected
  provider route uses a separate single-run inference record. A batch
  admits up to four independent assignments, subject to every grant’s
  narrower batch bound. Output remains in input order and names each attempt.
  Dependent groups and corrections require separate, ordered invocations.
- `--recover` observes the same original process or verifies and publishes
  its settled handover if necessary. It never sends the original prompt again.
- `--cancel` records a stop request for the positively identified original
  supervisor and worker. The supervisor owns signals and descendant
  settlement. The original claim and slot remain held pending readback.
- `--release-slot` requires the latest attempt’s exact settlement and a separate
  protected release receipt. `--release-claim` requires the same settlement,
  slot release and verified assignment closure. Both retire records under
  the host registry for later audit. Neither gives Git, task update, profile
  provisioning, publication or delivery acceptance authority.

Stdout contains the JSON outcome. A foreground run emits structured milestone
and heartbeat JSON lines on stderr. Use `readHandoff` with the retained expected
request and runtime to validate the final result. Treat running, unknown,
incomplete, blocked, capped and stopped states according to the retained
authority and [worker-runtime.md](worker-runtime.md).

## Input and authority

The input has `schemaVersion: 1` and `assignments`. Each entry has `request`
(the [portable worker request](worker-handoff.md)), `approval`, `grant` and
`host`. The last three are `{ path, sha256 }` locators. The approval and grant
paths also appear in the portable authority object. The implementer uses
one fresh evidence root, exact mutable file paths, a positive budget in
minutes and the required captures `native.txt`, `lifecycle.jsonl`,
`stdout.jsonl`, `stderr.log` and `launch.json`.

Approval and execution grant both carry `schemaVersion: 1`, `kind`,
`workspace`, `change`, normalized `repository`, exact `plan`, `planDigest`,
`orchestrator`, `authorSession`, `mode` (`task-guided` or `goal-first`),
`policyRevision` (integrated policy commit) and attached `branch`
(`refs/heads/...`). Approval is `exact-plan-approval` for Task-Guided or
`exact-goal-approval` for Goal-First and carries `approved: true` and
`approvedAt` (Unix milliseconds).

The separate `local-execution-grant` adds these fields.

| Fields | Binding |
| --- | --- |
| `approvalSha256`, `hostSha256`, `requestSha256` | Exact approval, host config and portable Markdown request. |
| `localOnly`, `stop`, `mutablePaths`, `restrictions` | True, matching stop and scoped output paths, and retained restrictions. |
| `head`, `checkoutIdentity` | Exact clean launch HEAD and checkout device/inode as decimal strings under `device` and `inode`. |
| `eligibleTasks`, `accepted`, `knownWorkspaces` | Eligible native task IDs, ordered accepted predecessors, and explicitly known sibling clones. |
| `issuedAt`, `expiresAt`, `limits` | Grant time fence in Unix milliseconds and positive `timeoutMs`, `stdoutBytes`, `stderrBytes`, `maxTurns`, `totalMs`, `groupMs`, `batchSize`, plus nonnegative `corrections`. |
| `inference` | Protected locator for the separate one-run provider authorization. |
| `overrideSha256`, `continuation` | Null unless independently authorized. Overrides pin canonical override bytes. Continuations pin a protected record. |
| `normalizedPlanDigest` | Additional task-normalized Git plan digest for Goal-First. |

Limits are capped at 600,000 ms per worker, 8 MiB per stream, 128 native
turns, 180 minutes per assignment, eight corrections and four batch members.
Native sandbox preflight consumes the held wall-clock grant. Successors
inherit the original time fence and can narrow limits. Each accepted
predecessor is `{ task, candidate, receipt }`. Its `accepted-dependency`
record binds `task`, `change`, `candidate`, `plan`, `planDigest` and
`verdict: "pass"`. The runtime checks real Git ancestry, the planning bytes
and current native checkbox order under the claim. It checks known
worktrees and clones for overlap. The orchestrator supplies accepted evidence
from the delivery gates and records the actual approved authority.
The inference record has `schemaVersion: 1`,
`kind: "worker-inference-authority"`, `attempt`, `requestSha256`,
`hostSha256`, `orchestrator`, `maxRuns: 1` and `expiresAt`.
Its time fence fits inside the local execution grant.

The independent `host` locator pins a `schemaVersion: 1` host binding with
`runtimeSha256`, `pair`, `override` and `restrictions`. A complete pair has
`implementer` and `reviewer`. Restrictions enumerate `allowedClients`,
`allowedModels` and `allowedProviders` and set `requireDistinctModels`.
An override is null or `{ attempt, expiresAt, pair }` and passes the same
checks as a default pair. See [worker-runtime.md](worker-runtime.md) for
role, supervisor and release record details.
