# Design

## Context

Item 0.5 provides pure charter and ledger checks; it does not launch a worker. The existing terminal adapter serves several clients and its ordinary Claude tool policy is not an OS read-only boundary. The interim launcher passed the empty-packet probe on Claude Code 2.1.330 and Bubblewrap 0.9.0; that observation qualifies neither the unbuilt CLI nor OAuth.

## Goals / Non-Goals

Prove exact review inputs, confinement and handover admission independently. Preserve existing strict candidate acceptance, the charter-v1 policy and all delivery authority boundaries. No new backend, broad host bind, ambient credential fallback, publisher access from the reviewer, or new remote action.

## Decisions

1. **Separate local preparation and external review.** Use a strict versioned JSON schema with no unknown/duplicate fields or command-bearing fields. Compare candidate input to independently retained full base/target SHA, plan SHA/digest, gate and diff identity; approach uses guard-inventoried raw input hashes, fixed charter and ledger. `--prepare` emits only explicitly approved regular-file bytes outside the checkout, scans exports for sensitive content, and commits to the ordered manifest. `--check` recomputes identities and hashes before launch with no provider access. Include exact literal verdict and target-SHA templates, never abbreviations or guessed verdicts. Split over-limit diffs deterministically into bounded packets with exact file/hunk assignment, including deletion/rename context; no silent truncation. Aggregate only a complete same-target packet set, preserving all findings and limits. Reject inputs that cannot be reviewed within the approved limits, including files that cannot be read whole.
2. **Contain the process and the credential path.** Use the minimal-root Bubblewrap `--unshare-all` and host Unix-socket `inference.sock` pattern instead of plan mode, host networking or mounting the checkout. Expose only the exported files, required read-only runtime/control mounts and the approved relay; private scratch is the only writable filesystem. Scrub environment; nothing from live home/config, Git metadata, publisher roots or unrelated sockets is mounted. Pin the binary/version, effective model and session, use `dontAsk` and exact `Read`, disable persistence, extension discovery and nonessential traffic, and set finite wall/turn/cost limits. Relay only the approved Anthropic inference methods/paths over verified TLS; no redirects, arbitrary destinations, discovery or raw secrets in request, argv, sandbox environment or captures. Support explicit host-configured dedicated reviewer UID/broker and same-UID key-only 0400 routes with the key kept host-side; document the weaker same-UID distinction. Support an explicitly selected dedicated scoped OAuth route only when compatible with the same isolation/egress and startup checks; no live OAuth directory, no policy override, and no claim of qualification without route-specific evidence. If an OAuth route needs managed policy, require administrator authorization and verified ownership/effective policy. No automatic route switch or shell secrets sourcing. Group 3 qualifies the pinned default relay pairing; alternative routes remain unqualified until separately proved.
3. **Probe, audit and verify before admitting results.** Run the P4 synthetic empty-input `--probe` automatically immediately before a data-bearing launch under the identical pinned settings and route, with a fresh separate session. Audit the real stream too: one matching init and terminal result, empty inventory except `Read`, no unexpected tools or side flows, only exact whole-file Read paths and successful coverage of every assigned file. A preflight is not a pre-exposure attestation of the second process; stop if policy requires that stronger ordering and it is not enforced. Keep closed raw captures separate from the native extracted report and sealed result/status. Keep candidate admission under existing `readHandoff` / candidate rules; keep `charter-v1` native receipt, ledger, deferrals and advisory semantics distinct (do not coerce them into candidate no-findings). Strict parsing rejects missing, extra, duplicate, wrong-type or inconsistent fields; retain invalid receipts and use one verified `retry-launch` at zero correction cycles via the existing decision, never resetting the ledger/budget or converting invalid output into approval. `--verify` reads back the complete manifest and sealed identities without contacting the provider.
4. **Harden shared adapter boundaries without widening other routes.** In the integrated parent, `executeTerminalAdapterAttempt` uses `spawnSync` with a timeout at `terminal-adapters.mjs:781–787` but no exact-tree quiescence proof (`1151615162`). The stream copy and publication path is at `788–799`, `829–836`, `890` and `worker-handoff.mjs:211–225` (`1151615159`); enforce independent bounded streams and byte/aggregate limits before buffer copying/publication, and keep distinct timeout/quota/native outcomes. Transport directory and writes are at `terminal-adapters.mjs:752–768` and `793–797` (`1151615150`); require verified parents, preflight `lstat`, exclusive no-follow creation and regular single-link sinks with no overwrite or fallback. Preserve bounded partial evidence, verify tree identity before signaling and quiescence before successor/replacement or successful publication, and do not signal an unverified process. Exercise with disposable synthetic processes/files and preserve existing non-Claude interfaces and role qualification.

## Risks / Trade-offs

- Export scanning is defense in depth, not proof of no sensitive content: only operator-authorized exports leave the host, and Anthropic sees those bytes. Fail closed on unresolved exposure.
- Packet splitting costs more launches and can fragment context; retain common review context, explicit coverage and one target across all parts. Partial coverage does not clear a gate.
- Linux/WSL confinement depends on host namespaces/runtime and filesystem primitives; refuse weaker fallbacks. Other platforms can package and exercise offline fixtures without claiming native support.

## Migration Plan

Keep the route opt-in. Ship the complete skill and optional bundle with synchronized operator docs and version bumps, retaining the prior approved procedure until the new route is qualified. Stop or roll back package use if qualification fails; preserve evidence and do not change installed profiles. Live trial and its results are explicitly deferred to task 3.1; separate authority is required. A later implementation run uses standalone Codex native `-s workspace-write --ephemeral`, scrubbed PATH, isolated HOME/XDG, `--enable skip_host_skill_discovery --ignore-user-config`, no outer Bubblewrap, with independent Bubblewrap-contained Read-only Claude Code review under the authorized binding.
