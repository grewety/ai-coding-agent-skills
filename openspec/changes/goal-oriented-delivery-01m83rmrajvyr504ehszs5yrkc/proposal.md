# Proposal

## Why

The current workflow asks operators to freeze ordered task definitions even for coherent local work whose implementation can safely adapt. A concise, verifiable goal and independent result review can reduce those pauses while keeping staged authority and exact candidate evidence.

## What Changes

- Make Goal-First the default for reversible local work when the verified integrated parent explicitly opts in. Bind a local run to an approved Goal Contract with outcome, allowed scope, hard operator invariants, exclusions, verifiable acceptance gates and finite budgets. Keep one native outcome checkbox, allow implementation choices and obsolete legacy assumptions to adapt, and require passing executable gates and fresh independent read-only review of the exact candidate.
- Keep Task-Guided delivery for prescribed methods, required execution order or staged authority. Retain the exact frozen SHA and plan digest, ordered dependency and authority gates, and inherited review and continuation rules. This change follows that inherited policy. Its proposed opt-in affects only future changes after integration.
- Check goal alignment at phase boundaries and after corrections. Use the bounded routine correction loop for in-scope failures and stop for invariant drift, unresolved ownership or environment failures, exhausted budgets, or missing authority. Allow bounded disposable-scratch discovery for breaking upgrades before locking a contract.
- Package read-only preflight, policy, workspace reconciliation and deterministic JSON status and handover commands. Expose lossless gate capture, evidence sealing and closeout assertion commands, including a pre-finish check that verifies current-spec promotion. Preserve one dedicated implementation worktree and native tasks as the sole mutable progress authority.
- Address the open Aikido change-guard findings 1151615165 and 1151615147 with ignored-file-aware candidate cleanliness, exact-SHA disposable gate checkouts and shared aggregate planning inventory limits. Preserve existing fail-closed Git and evidence checks.
- Require separate explicit single-run authorization for paid or external verification, tunnels and external app-triggered checks. Bound disclosure and any tunnel to the approved built artifact, check potential automation before a push, and clean up after the authorized run. When declared, support local try-out, accessible-name checks and separately authorized PR deploy-preview acceptance.
- Bring the delivery and routing skills, integrated contributor contract, operator workflow, distribution version inventory and acceptance tests into agreement.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `openspec-integration` — Delivery mode and approval identity, bounded authority, deterministic status and handover, phase alignment, safe candidate and planning checks, and promotion readiness.
- `lossless-closeout-evidence` — Runnable evidence capture, sealing and offline closeout readback verification through the existing evidence model.

The optional UI flow declares and routes acceptance gates. The distribution itself adds no web app.
- The proposal grant covers drafting, the proposal-time issue, pinned approach review and a local plan freeze. Exact-plan approval and a later execution grant remain pending. Publication, external/irreversible actions, and any paid retry require separate authority.
