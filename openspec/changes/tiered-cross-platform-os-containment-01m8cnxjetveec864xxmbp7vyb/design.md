# Design

## Context

The integrated parent `39606f64b148ffad3b7fa7d268f5eb64a7868097` uses a pinned contained Claude reviewer and a separate exclusive native Codex worker route. Reviewer host validation caps each invocation at 300000 ms. The shared setup command accepts external role inputs and uses an exact preview digest for writes. Installed discovery is evidence of presence only. Existing replay inputs were minted before tier and driver fields existed.

## Goals / Non-Goals

Keep admission, live supervision and offline evidence tied to the same effective tier, driver and role. Define the mandatory Linux path and the conditions that keep optional platform paths closed. Leave packet construction, process profiles, stream adapter internals and other implementation choices adaptable within the Goal Contract. Native Windows and macOS qualification requires its own future evidence and authority.

## Decisions

1. **Separate trust boundaries.** Tier A keeps host-side authentication and a private relay as its only inference path. For Linux it keeps private scratch, pinned minimal rootfs, isolated namespaces, denied direct network and OS-read-only `/review`. Tier B is a deliberate selection for clients needing local session state. It hides ambient HOME and profile paths at the OS boundary, mounts only approved read-only runtime data, provides private scratch and exposes only a dedicated 0700 auth-only root to client authentication. The dedicated state and provider HTTPS are within Tier B's declared exposure. Neither permission carries into Tier A. Verify the effective runtime and preflight before real input exposure.
2. **Keep role-specific OS enforcement.** A reviewer receives an immutable packet at `/review` and starts with one native read tool. A Tier B non-Codex implementer may use a qualified `linux-bwrap` role route with write access scoped to its approved worktree and protected task, Git and evidence state. Codex 0.172.0 keeps native named workspace-write, with its verified dedicated home and OS controls, and identifies the actual native driver in evidence. Wrapping Codex would interfere with the native sandbox it must prove.
3. **Bind configuration and evidence across the same route.** New records bind `containmentTier` and `osDriver` for host, launch, status and receipt. Safe auto-pinning is a discovery input to preview, with independently verified executable and library identity, safe output paths and no auth material readback. Explicit confirmation binds exact current preview bytes. Setup does not qualify a backend. Legacy readers recognize original schema and bytes. New `timeoutMs` inputs keep a 300000 default and permit up to 600000, within the run and authority deadlines. A longer timeout grants no added turns, spend, network, or retries.
4. **Qualify end-to-end evidence.** The Grok 1.0.92 subscription pilot uses `grok-4.7` with `xai-oauth` and `read_file`. The identified client has a whole-file read surface and native streaming output. The reported single-read cap is 100,000 bytes for review files capped at 65,536 bytes. Treat those as exact-binary observations to reverify in qualification. Prove the effective single-tool inventory and response bytes against sealed packet files, match request and result IDs under serial and parallel reads, and replay the exact framed receipt offline. A read limit, stream association or receipt gap blocks qualification. Use only benign synthetic files and independent exact status/configuration pins. Under a distinct grant, establish the same evidence discipline for native Codex workspace-write and complete settlement.
5. **Require native proof per optional driver.** Linux is the first implementation and qualification target. Windows has an optional `windows-container` contract using Windows container/profile and ACL restrictions with process-tree controls. Its integration wiring can start from Windows Node or WSL2 interop. A Windows-side prerequisite report verifies installed required Windows AI client executables and container, job and filesystem controls before tests launch. A WSL Linux executable is insufficient. The optional `macos-seatbelt` contract needs native Seatbelt evidence for role-specific filesystem, auth and network boundaries. Both require their own matching native evidence to admit real workload. Platform mismatches, missing Windows clients and unqualified controls produce explicit dispositions.
6. **Keep approval boundaries executable.** The operator retains changes to hard invariants, tier defaults or scope, exact plan approval, bounded local execution and protected finish. Integrated planning review uses Claude Code 2.1.330, `claude-sonnet-4-6`, pinned Bubblewrap 0.9.0 and the `same-uid-key` relay. The private host configuration has SHA-256 `bb71a156d9c8e537cfe510401813cc88334456e213e9b314b67b1b2c48d03b0c`, packet concurrency 2 and a USD 2.50 per-invocation cap. Use the standalone Node `review-candidate.mjs` invocation with offline prepare/check and sealed replay. Low-touch limits remain ten reviews and USD 25 total. Planning review admits advisory Low findings only with IDs and allows only charter-declared deferrals or boundaries. Packet defects use the packet-gap path and consume zero correction cycles. Up to three automatic planning corrections are distinct from ten local execution corrections. Each external Linux trial needs its own bounded grant.

## Risks / Trade-offs

- Dedicated auth and direct provider access change the exposure of Tier B. Explicit tier selection, minimal dedicated state, hidden ambient paths, approved provider-only connectivity, redacted evidence and no fallback keep that exposure bounded.
- Native launch success can coexist with incomplete audit. Missing reads, wrong bytes, truncation, unexpected tools, binding drift or unsettled process trees prevent acceptance. Preserve the exact failed predicate and sealed record.
- Host prerequisites and optional support can drift. Validate installed Windows executables before test entry and require native evidence for any support statement. Continue to distinguish package verification, standalone offline checks and qualified live results.

## Migration Plan

Existing Claude schemaVersion 1 files and historical captures keep their original bytes and reader semantics. Review and ship the Linux tier architecture and verified setup with complete packages, synchronized documentation and promoted specs. Keep all unproved routes unavailable and retain exact sealed dispositions for failed authorized trials. Operators can keep the original scoped Tier A host and evidence. Recover from a defective configuration by withholding the affected route and selecting a previously qualified binding through the normal operator boundary, never through an automatic downgrade.
